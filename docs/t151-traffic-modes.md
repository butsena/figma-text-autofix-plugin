## Готово в коде

- Schema v1: необязательное для старых клиентов поле `traffic_mode=production|test`. Новый отправитель задаёт его всегда. Явные null, undefined, пустая строка, иные типы/значения и smoke+production отклоняются; неизвестные приватные поля по-прежнему не сохраняются. Старые клиенты без поля остаются совместимыми.
- Приёмник T-151-1 сохраняет восьмой столбец H `traffic_mode`; отсутствие поля превращается в `unknown` только при хранении. Старые пустые H не переписываются. A:G сохраняются. Перед каждой записью заголовок сверяется: неподготовленная или занятая H не перезаписывается молча.
- T-135 replay сравнивает также режим: тот же ID с тем же содержимым/режимом — duplicate; смена режима — conflict. Пустая историческая H и unknown совместимы. Семь событий, source, failed/recovered и правила данных T-140 сохранены.
- GET сообщает `collector_revision=T-151-1`, `traffic_modes=[production,test]`, `traffic_mode_storage=events!H`. Это capability кода, не доказательство происхождения запросов, чистоты истории или готовности формул.
- smokeAppend теперь явно test, версия служебной пробы `0.0.0-collector-test`; onceSetup не вызывается этой функцией. Нормальный deployment не запускает smokeAppend/onceSetup/setupDashboard.

## Сборки и проверка выпуска

Команды выполняются из корня принятого checkout. Реальный номер следующей Community-публикации выбирается при подготовке выпуска, не этой задачей.

```sh
npm run build
PLUGIN_VERSION=0.22.0-t151.1 npm run build:qa
PLUGIN_VERSION=0.22.0-t151.1 npm run build:release
```

Первая команда выключает отправку; QA создаётся в dist-qa, release — в dist-release. Номер выше — технический номер кандидата T-151, не утверждённый выпуск Community. Включение ANALYTICS без явного режима/валидной версии проваливает сборку. Конфликт режима с выбранной командой тоже ошибка. Общий исходный конфиг не редактируется на время сборки; обычный dist не перезаписывается QA/release-командами.

Каждый специальный build выполняет **готовый main.js** в Node VM с перехватом fetch: проверяет open и ошибку отсутствующего слоя, правильные version/mode/endpoint и отсутствие приватных данных. Запросы не пересылаются в сеть. Build-info содержит commit, dirty, SHA256, режим, версию и endpoint. Проверка VM не заменяет Figma и не обещает реальную доставку.

```sh
PLUGIN_VERSION=<версия выпуска> ANALYTICS_REPORT_PROOF=<файл сверки рабочего отчёта> npm run check:release
```

Отдельная проверка запрещает QA-файл, dirty/чужой commit, неправильный манифест, изменённый main.js и неверную версию. Затем проверяет GET действующего приёмника и подтверждение рабочего отчёта. Не отправляет POST и не публикует плагин. Файл сверки создаётся только после разрешённого переноса и проверки **рабочей** книги, не копии:

```json
{"spreadsheetId":"1hp5YccbllfFn0cYRkvp6ClWEXbx5Es1R79FFLsqfHqM","revision":"T-151-1","testsExcluded":true,"formulaErrors":0,"verifiedAt":"<фактическая UTC-дата сверки>"}
```

Это контроль процесса выпуска, не криптографическое подтверждение данных и не замена приёмки. До переноса такой файл не создан. Успешный локальный build сам по себе не означает разрешение публикации.

Другие значения H и smoke+production попадают в диагностику, не рабочие показатели. Суффикс -qa без признака не считается доказательством теста.

Добавлена вкладка «Режимы запусков»: количество **записей** production/test/unknown/ошибок данных по всем 41 прежним UTC-периодам, общий поток и первая полученная production-запись. Это не люди, макеты, правки или число уникальных запусков. Остались структура и 10 существующих графиков; коэффициенты, часы/рубли, A:G и история не переписаны. Подпись существующего итога явно предупреждает о неизвестной истории.

Исправлена Методика!B35: дата первого не исключённого запроса стала 22.10 вместо 21.10.2026 — прежняя формула включала smoke. Зависимые подписи обновляются сами; правки/часы/рубли от этого не меняются. Это начало наблюдаемых не исключённых запросов, а не доказательство реальности неизвестных запросов 22.10.
