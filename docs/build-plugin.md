# Сборка плагина

Команды выполняются из корня актуальной локальной копии проекта.

| Цель | Команда | Манифест для импорта в Figma | Аналитика |
| --- | --- | --- | --- |
| Обычная работа | `npm run build:release` | `dist-release/manifest.json` | production |
| Проверка | `npm run build:qa` | `dist-qa/manifest.json` | test, исключена из рабочих показателей |
| Разработка без отправки | `npm run build` | `manifest.json` | выключена по умолчанию |

Версия для QA и рабочей сборки берётся из `package.json`. Вводить переменные или редактировать исходники перед каждой сборкой не нужно. Сейчас сохранён прежний технический номер кандидата `0.22.0-t151.1`; это не назначение номера публикации Community. При подготовке следующего выпуска номер обновляется один раз в package.json и package-lock.json (например, `npm version X.Y.Z --no-git-tag-version`). Явный `PLUGIN_VERSION` по-прежнему может переопределить номер кандидата; пустое или неверное значение вызывает ошибку.

В Figma один раз импортируйте нужный манифест через Development → Import plugin from manifest. После повторной сборки перезапустите подключённый плагин. QA и release лежат в разных папках и не перезаписывают обычный dist. Проверки выполняйте QA-версией: рабочая сборка не может определить по тексту, что вы тестируете плагин.

Сборка проверяет готовый файл с перехватом сети, не отправляет аналитические события и ничего не публикует. Отдельная проверка выпуска `npm run check:release` также берёт версию из проекта; ей по-прежнему нужен `ANALYTICS_REPORT_PROOF` — файл подтверждённой сверки рабочего отчёта. Проверки чистоты кода, режима, commit и контрольной суммы сохранены. Для локального использования эта проверка публикации не нужна.

Исторические команды с явной версией в документах T-151 остаются работоспособными. Если переопределяли версию сборки, передайте тот же номер при проверке выпуска.
