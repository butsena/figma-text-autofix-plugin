# T-135: подсказки и свои варианты орфографии

## Готовый результат и границы приёмки

В успешном `manual_fix_complete` для `orthography/applied` появляются необязательные `source` и `event_id`. Старые клиенты принимаются без изменений. Схема v1, семь типов событий и семь колонок `events` сохранены. Слова, пары замен, текст макета, имена и Figma ID не отправляются.

Код подготовлен отдельно от внедрения. На 28.10.2026 рабочий приёмник остаётся T-140-1; рабочая таблица не изменена. Публикация Community и номер версии не менялись. Новые случаи QA №51 требуют ручной проверки, результат пользователя за них не подставлен.

## Что означает источник

| Ситуация | `source` |
| --- | --- |
| Итоговый вариант совпадает с исходной подсказкой, включая повторный ввод или вставку | `suggested` |
| Подсказка изменена или исправление введено без готовой подсказки | `custom` |
| Старый UI или недопустимые метаданные не позволяют определить источник | `unknown` |

Сравниваются исходная подсказка и фактическая замена после существующей обработки ввода. Только для сравнения удаляются пробелы по краям, применяется NFC и нижний русский регистр. Внутренние пробелы и е/ё различаются. Сам текст замены эта классификация не меняет.

Событие создаётся после подтверждённого изменения текста, как в T-141. Пустой ввод, отсутствие изменения, устаревшая карточка, ошибка и повторное нажатие не создают успех. Пропуск и выбор формы не получают `source`/`event_id`. Новые автоматические правки после ручного действия учитываются отдельно по T-142.

Одноразовый случайный `event_id` создаётся в плагине после успеха. Приёмник под блокировкой ищет его во всей сохранённой колонке payload: повтор того же содержимого возвращает `duplicate` без новой строки, конфликт содержимого возвращает `event_id_conflict`. Разные ID считаются разными исправлениями. Сетевые повторы/очередь не добавлялись. Дедупликация действует, пока исходная строка сохранена; старые события без ID ведут себя как прежде.

## Отчёт

[Проверочная копия](https://docs.google.com/spreadsheets/d/1r4fpfkvr7ki021FpKdMNBiAfPk4P7eoLuvcyUpYWI4s/edit#gid=1350135) — снимок рабочей книги, без синхронизации новых событий. В ней новая вкладка «Источники орфографии» A1:F46, ссылка с «Результаты» A69 и определения/контроль в «Методика» A53:F65. Два старых пояснения уточняют различие исторических нажатий и успешных замен; прежние формулы и графики сохранены.

Разбивка использует те же 41 периода и границы L/M вкладки «Результаты». Дата события — `server_time` UTC, начало включительно, конец исключительно. `LOWER(TRIM(plugin_version)) = smoke` исключается. Учитываются только `manual_fix_complete` с `kind=orthography/action=applied`.

`Всего = По подсказке + Свой вариант + Источник неизвестен`. Неизвестное считается остатком: старые строки без поля не переразмечаются. При отсутствии событий доля определённого источника — «—». Нули suggested/custom в истории не доказывают отсутствия таких действий.

«Методика» B54 показывает первое полученное рабочее событие с допустимым полем источника, включая `unknown`; это не дата кода или публикации. B59 — охват новым полем, B60 — доля определённого источника, B65 — контроль суммы по 41 строке (ожидается 0). Это не проверка полноты доставки. T-135 не добавляет часы и рубли поверх прежней оценки.

## Порядок внедрения после явного разрешения

1. Сохранить код действующего приёмника и актуальное состояние целевых диапазонов таблицы. Проверить отсутствие новой одноимённой вкладки и совпадение структуры периодов с проверочной копией.
2. Обновить код **существующего** Apps Script на `scripts/analytics-apps-script.js`, сохранить и обновить существующее развёртывание новой версией. URL и права доступа сохранить. `onceSetup`, `setupDashboard`, `smokeAppend` не запускать.
3. Проверить GET: `collector_revision=T-135-1` и три `spelling_sources`. Затем выполнить согласованные пробы с `plugin_version=smoke`: suggested/custom/unknown, повтор одного ID, конфликт ID и старый payload. Проверить отсутствие повторной строки и отсутствие влияния на рабочие показатели.
4. Добавить разбивку и методику в рабочую книгу по проверенному плану точечных изменений. Не переносить `events` из копии, не очищать старые вкладки, не менять графики и коэффициенты. Повторно проверить все периоды, формулы и контроль суммы.
5. Проверить новую сборку в Figma по QA №51: принятие подсказки; ввод такой же подсказки; свой вариант; ввод без подсказки; пустой ввод и повторный клик. Проверить итоговый текст, одну строку на успешную замену и правильную группу. Проверочные события исключать из рабочих показателей через сборку `smoke`.
6. Записать фактические результаты и SHA сборки в QA/бэклог. Слияние PR, Done и публикацию выполнять после соответствующего принятия пользователем.

Откат: восстановить сохранённую предыдущую версию существующего развёртывания; новые необязательные поля при этом могут отбрасываться старым приёмником. Сохранённые события не удалять. В отчёте восстанавливать только добавленные диапазоны/вкладку из снимка, не перезаписывая поступившие события.
