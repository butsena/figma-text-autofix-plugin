# Text Autofix · Cian Text Rules

Плагин для Figma, который исправляет типографику и типовые нарушения редполитики Циана в выбранных текстовых слоях и макетах. Неоднозначные случаи показывает в отчёте и оставляет решение пользователю.

[Плагин в Figma](https://www.figma.com/community/plugin/1637103330071275318/cian-text-rules)

## Возможности

- **Типографика:** кавычки, тире, многоточия, лишние пробелы, неразрывные пробелы, оформление чисел и диапазонов.
- **Редполитика:** обращения на «вы», написание бренда и его склонение, терминология и словарные замены.
- **Буква «ё»:** автоматические замены по словарям и выбор в неоднозначных случаях.
- **Формы слов:** варианты, требующие решения по контексту, например «ищите / ищете» и «все / всё».
- **Орфография:** отдельная проверка на основе русского словаря Hunspell, подсказки и возможность указать своё исправление.
- **Отчёт:** применённые автоматические правки, вопросы для ручной проверки, объяснения правил и переход к соответствующему слою.

Примеры правил:

| Исходный текст | Исправление |
| --- | --- |
| `на ЦИАН` | `на Циане` |
| `он-лайн` | `онлайн` |
| `риэлтор` | `риелтор` |
| `далее` | `дальше` |
| `"Квартира"` | `«Квартира»` |
| `5 %` | `5%` |

Результат зависит от контекста, состава правил и загруженных словарей.

## Использование

1. Выделите текстовые слои или содержащие их фреймы в Figma.
2. Запустите плагин. **Автоматические правила сразу изменяют текст в выделении.**
3. Посмотрите отчёт о применённых правках.
4. Разберите оставшиеся вопросы: подтвердите подходящий вариант, внесите своё исправление или пропустите предложение.
5. При необходимости включите проверку орфографии кнопкой в интерфейсе плагина.

Опубликованная версия сейчас доступна участникам CIAN PLC в Figma. Публичность этого репозитория не меняет доступ к опубликованному плагину. Для локального запуска используйте инструкцию ниже.

### Ограничения

Плагин проверяет заданные правила и словари. Он не заменяет полную вычитку, не проверяет продуктовую логику и не гарантирует отсутствие ошибок. Орфографическая проверка может предлагать неверную форму слова или не распознавать отдельные слова — проверяйте предложения по контексту.

Для изменения текстовых слоёв должны быть доступны их шрифты.

## Словари

Редактируемые словари вынесены в отдельные репозитории. Изменения в них подхватываются при следующем запуске плагина без пересборки кода.

| Репозиторий | Назначение |
| --- | --- |
| [text-autofix-replacements](https://github.com/butsena/text-autofix-replacements) | Словарные замены и формы |
| [text-autofix-no-period](https://github.com/butsena/text-autofix-no-period) | Исключения для определения границ предложений |
| [text-autofix-word-forms](https://github.com/butsena/text-autofix-word-forms) | Неоднозначные формы для выбора пользователем |
| [text-autofix-spelling](https://github.com/butsena/text-autofix-spelling) | Hunspell, дополнительные слова и исключения орфографии |

Для части словарей предусмотрены встроенные копии. Большой орфографический словарь загружается отдельно; доступность орфографии зависит от его успешной загрузки или наличия сохранённой копии.

Подробнее: [карта словарей](docs/dictionaries-overview.md), [орфография](docs/spellcheck-hunspell.md).

## Данные и сетевые запросы

Проверка текста и применение исправлений выполняются на устройстве пользователя. Содержимое макетов не отправляется в продуктовую аналитику.

Сетевой доступ используется для загрузки словарей с GitHub и, в сборках с включённой аналитикой, отправки обезличенных событий через Google Apps Script. События содержат технические сведения о действиях, счётчиках, длительности этапов и сбоях.

В обычной локальной сборке аналитика по умолчанию выключена. Подробности: [сбор событий](scripts/analytics-collector.md).

## Локальная установка

Нужны Node.js с npm и Figma с возможностью импортировать плагин для разработки.

```bash
git clone https://github.com/butsena/figma-text-autofix-plugin.git
cd figma-text-autofix-plugin
npm ci
npm run build
```

В Figma откройте **Plugins → Development → Import plugin from manifest** и выберите `manifest.json` в корне проекта. После сборки манифест использует файл `dist/main.js`.

Для пересборки при изменении исходников:

```bash
npm run dev
```

После пересборки перезапустите плагин в Figma.

## Команды

| Команда | Назначение |
| --- | --- |
| `npm run build` | Локальная сборка; аналитика по умолчанию выключена |
| `npm run dev` | Сборка в режиме наблюдения за файлами |
| `npm test` | Автоматические тесты |
| `npm run test:watch` | Тесты в режиме наблюдения |
| `npm run build:qa` | Проверочная сборка в `dist-qa/` с режимом аналитики `test` |
| `npm run build:release` | Рабочая сборка в `dist-release/` с режимом аналитики `production` |
| `npm run check:release` | Проверка готовности выпуска по принятому процессу |

QA- и release-сборки используют настроенный в проекте приёмник аналитики. Для знакомства с кодом и самостоятельных экспериментов используйте обычную локальную сборку. Сборка сама по себе не публикует новую версию в Figma.

Подробные условия и параметры: [инструкция по сборке](docs/build-plugin.md).

## Разработка и обратная связь

Для сообщения об ошибке укажите исходный текст, ожидаемое исправление, фактический результат и версию плагина. Если возможно, приложите небольшой пример без конфиденциальных данных.

Изменения правил проверяйте автоматическими тестами и в Figma. Порядок работы описан в [процессе разработки](docs/development-workflow.md) и [инструкции QA](docs/qa-workflow.md).

`backlog.yaml` — исторический снимок миграции, а не актуальная очередь задач.
