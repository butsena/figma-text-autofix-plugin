# Приём аналитики · T-140 / T-135

`analytics-apps-script.js` — самостоятельный файл для Google Apps Script. Реализация
`T-135-1`, схема событий по-прежнему **v1**. Это разные номера: ревизия кода,
версия deployment Apps Script и версия публикации плагина не заменяют друг друга.

## Правила приёма

- Только семь событий и закрытые категории/этапы/коды из `src/analytics/schema.ts`.
  Тест `src/analytics/collector.test.mjs` сверяет списки с клиентом.
- `manual_fix_complete` может содержать `source` только при
  `action: "applied"`, `kind: "orthography"`. Закрытый список:
  `suggested` — выбран вариант плагина; `custom` — собственная замена;
  `unknown` — новый клиент не смог определить источник. Слова и варианты
  в это поле не передаются. Неверное значение или `source` у пропуска,
  confirm, choice либо другого события отклоняет запись целиком до таблицы.
  У старого клиента отсутствие `source` разрешено: поле не дописывается,
  исторические строки и их семантика не меняются. Семь колонок events сохранены;
  источник находится только внутри `payload_json`.
- В том же успешном орфографическом событии разрешён необязательный `event_id`:
  одноразовая случайная строка `evt_` и 12–60 символов `[A-Za-z0-9_-]`,
  общая длина 16–64. Это ID одной записи, без связи с человеком, файлом,
  слоем или словом. Новый клиент создаёт его один раз на реальный успех;
  при повторной доставке того же события ID не меняется. Неверный формат
  или ID у другого события/действия отклоняет запись целиком.
- Envelope и payload должны быть объектами, не массивами. Каждое событие
  собирается заново только из разрешённых полей. Лишние поля, включая тексты,
  ID, `message` и `stack`, отбрасываются без сохранения и логирования. Это правило
  действует и для пустого payload у `spellcheck_requested`.
- Неизвестное событие, категория, действие, этап/код, неверный тип или обязательное
  поле отклоняют всю запись до обращения к таблице. Ответ содержит только
  фиксированный безопасный код ошибки, без исходных значений.
- Счётчики и длительности — неотрицательные safe integer. У auto
  `applied + not_applied = found`, сумма категорий равна `applied`.
  Нулевые категории не сохраняются, как в клиентском сериализаторе.
  У scan `found_fixes` означает auto, поэтому сумму confirm/choice с ним не сравниваем.
- Дата — действительная UTC-дата в формате `Date.toISOString()` с миллисекундами.
  Версия — `X.Y.Z` с необязательными безопасными prerelease/build-частями,
  до 32 символов. Историческое значение `smoke` разрешено явно; фильтр отчёта
  не меняется. Сессия — 8–64 символа `[A-Za-z0-9_-]`.
- Лимит тела 4 000 символов сохранён. Синтаксически неверный JSON отклоняется
  как ошибочный ввод. Сырые запросы не логируются.
- Перед записью строка проверяется повторно. Строки с формульным началом
  экранируются апострофом; обычные даты/версии уже ограничены форматом.
  Одна запись добавляется целиком под прежней блокировкой. Ошибка блокировки
  не начинает запись, ошибка хранилища освобождает блокировку.

## Повторная доставка успешной орфографической замены

Под одним `ScriptLock` приёмник ищет точный JSON-фрагмент `event_id` во всём
использованном столбце G листа events, без кэша и ограничения последними строками.
Если версия плагина, имя события и нормализованный разрешённый payload совпали,
ответ — `{ "ok": true, "duplicate": true }`, новой строки нет. Другие
client/server time и session_id не меняют это сравнение. Повтор с тем же ID,
но другим содержимым отклоняется как `event_id_conflict`. Два разных ID с
одинаковыми остальными показателями дают две записи. У legacy без ID обе
доставки сохраняются, как прежде; историческая дедупликация не выполняется.

ID хранится только в payload_json и живёт столько же, сколько сама строка.
При ручном удалении строки или ID защита для этого события утрачивается.
Проверка не доказывает происхождение запроса и не гарантирует доставку:
`trackAnalytics` делает один fire-and-forget POST без повторов и очереди.
Повторный клик дополнительно защищён проверкой результата и блокировкой
ручной операции из T-141. Новый транспорт или постоянный ID пользователя
не вводится.

Поиск использует документированный
[TextFinder](https://developers.google.com/apps-script/reference/spreadsheet/text-finder)
с буквальным поиском с учётом регистра. После append выполняется
`SpreadsheetApp.flush()` до снятия блокировки, как рекомендует
[документация Lock](https://developers.google.com/apps-script/reference/lock/lock#releaselock),
чтобы следующая доставка увидела сохранённую строку.

Основание защиты ячеек: Google указывает, что `appendRow` интерпретирует значение,
начинающееся с `=`, как формулу:
https://developers.google.com/apps-script/reference/spreadsheet/sheet#appendRow(Object)

## Совместимость соседних задач

Из проверки раскладки удалены отладочные POST на localhost со словами и вариантами
замены. Алгоритм подбора исправления сохранён. Поведенческие тесты раскладки и
проверки орфографии запрещают сетевые запросы во время локальной проверки текста.
QA #59 объединяет проверку этой границы и безопасного приёма событий; выполняется
на локальных имитациях, без отправки пробных строк в рабочую аналитику.

T-141 меняет момент подтверждения успеха. Текущие `action`/`kind` и
`choice_resolved` остаются совместимыми с этим приёмником; подтверждение выбора
исходной формы не требует нового поля. T-142 использует прежний
`auto_fix_complete` для добора после ручного действия; его суммы и категории
проверяются без изменений. T-135 согласованно расширяет клиентский контракт,
белый список приёмника и локальные тесты полем источника. Старый приёмник
`T-140-1` молча отбросит это поле, поэтому сначала требуется обновить приёмник
и проверить его GET, и только затем выпускать клиент с источником.

Общая гарантия полноты/повторной доставки остальных событий, отделение тестов
(T-134) и закрытия (T-145/T-146) остаются отдельными задачами.
Публичный endpoint не удостоверяет происхождение корректного по форме события.

## Проверка и выпуск

1. Запустить `npx vitest run src/analytics/collector.test.mjs src/analytics/schema.test.ts
   src/analytics/pipeline-events.test.ts src/analytics/track.test.ts`.
   Сервисы Sheets/Lock/ContentService в тестах заменены локальными имитациями;
   внешней сети и записей в рабочую таблицу нет.
2. Сохранить исходник и номер действующего deployment. Сравнить редактор с ним:
   несохранённые/чужие изменения нельзя заменять вслепую.
3. Заменить только код приёмника в существующем проекте Apps Script, сохранить,
   обновить **существующее** развёртывание новой версией, сохранив URL, владельца
   и доступ. Не создавать новый endpoint и не менять разрешения.
4. **Не запускать `onceSetup`, `setupDashboard` или `smokeAppend`** для обновления.
   `setupDashboard` очищает настроенный dashboard. Проверочный POST в рабочий
   поток не нужен: он загрязняет историю даже при обычном номере версии.
5. GET того же `/exec` должен показать `collector_revision: "T-135-1"` и
   `spelling_sources: ["suggested", "custom", "unknown"]`.
   Это проверяет код активного deployment без записи события, но не доказывает
   доставку POST, полноту истории или состав опубликованного плагина.
6. Сверить сохранность пяти листов, формул и настроек отчёта. Сохранить номер новой
   версии deployment и исходник. Для отката выбрать прежнюю версию того же
   deployment; прошлые данные не переписывать.

`npm run build:release` проверяет **локальную выпускаемую сборку**. Номер из
конфига и отсутствие debug-отправок в этом артефакте сами по себе не доказывают,
что именно он опубликован в Figma Community. Для публикации не менять номер
версии без нового номера Community. Рабочая сборка в `dist` другой сессии
не должна затираться проверочным build/dev.
